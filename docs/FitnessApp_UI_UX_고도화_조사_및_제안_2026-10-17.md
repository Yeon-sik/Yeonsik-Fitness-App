## 1. 목적과 판단

현재 운동·식단·신체·기록 기능의 큰 틀을 유지하면서, 상용 제품 수준의 디자인과 사용 경험으로 발전시킬 지점을 정리한다. 대상은 초보자, 꾸준히 기록하는 일반 사용자, 세밀한 분석이 필요한 숙련자 모두다.

**가장 먼저 집중할 단위는 운동 선택 → 현재 세트 기록 → 휴식 → 다음 세트 → 완료 요약이다.** 이 흐름을 대표 경험으로 완성한 뒤, 같은 입력·저장·피드백 규칙을 식단과 신체 기록에 확장한다.

현재 앱에는 Compose, 공통 디자인 토큰, 유리 효과, 탭 스와이프, 진입 애니메이션이 이미 있다. 다음 수준의 차이는 정보의 우선순위, 조작에 대한 확실한 반응, 화면 사이의 연속성, 기록을 해석하는 방식에서 만든다.

상업적 효과는 아직 가설이다. 기록 시간 감소, 오입력 감소, 저장 신뢰도 향상, 반복 사용 부담 감소를 실제 과제 수행으로 검증해야 한다. 경쟁 앱보다 우수하다는 결론은 아직 내리지 않는다.

## 3. 현재 앱 구조

### 3.1 실행과 내비게이션

현재 실행 흐름은 Java `MainActivity` → `ComposeView` → `ComposeAppScreen.install` → `AppRoot`다. Java 호스트와 일부 View 상호운용을 유지하면서 Compose와 Material 3로 화면을 구성한다. Room 의존성도 존재한다.

내비게이션은 `SavedStateHandle`, `FitnessNavigationHistory`, 직접적인 destination 분기를 사용하는 자체 상태 기반 구조다. 조사한 실행 경로에서는 AndroidX `NavHost`를 사용하지 않았다. 따라서 Navigation Compose 예제를 그대로 적용하는 방식으로 화면 전환이 완성된다고 가정하지 않는다.

| 영역 | 현재 확인된 구성 |
| --- | --- |
| 하단 탭 | 메인 / 피트니스 / 기록 / 설정 |
| 메인 | 오늘 상태, 빠른 이동, 근력·유산소, 식단, 체중, 활동 내역 |
| 피트니스 | 운동 개요, 근력, 유산소, 식단, 보충제, 루틴, 운동 세션·종목 상세·요약 |
| 기록 | 기록 / 통계 / 발전 내부 탐색 |
| 집중 화면 | 운동 세션·종목 상세·요약 등에서는 하단 탭을 숨김 |
| 복귀·스크롤 | 화면별 saveable state 사용. 하단 탭 클릭과 스와이프에는 서로 다른 복귀 정책이 있음 |

하단 탭 클릭 시 루트와 맨 위로 복귀하는 정책을 단순 버그로 단정하지 않는다. 시각 전환을 개선할 때 기존 동작을 보존하고, 정책 변경이 필요하면 별도 UX 검증 대상으로 다룬다.

### 3.2 이미 구현된 기능과 디자인

| 영역 | 확인된 구현 | 보존할 가치 |
| --- | --- | --- |
| 세트 입력 | 중량·횟수·RIR·완료·부하를 한 줄에 배치, 좁은 화면에서는 가로 스크롤 | 반복 입력의 밀도와 기존 사용자 조작 방식 |
| 입력 상태 | 세트 ID 등 의미 있는 식별자에 연결된 초안 보존, 키보드 Next/Done | 입력 중단·왕복에서 작업을 보호하는 기반 |
| 완료·휴식 | 세트 완료 저장 성공 후 자동 휴식 시작 | 기록과 다음 행동의 연결 |
| 식단 | 음식 찾기/이번 식단, 영양 합계·저장, 제거 Undo | 한 끼 단위의 조립 흐름 |
| 데이터 표현 | 미확인 칼로리, 데이터 충분성, 관찰 신호의 한계 표시 | 과장하지 않는 기록의 신뢰성 |
| 시각 토큰 | 라이트/다크, 고정 브랜드 블루, 공통 간격·모서리·타이포 | 화면 간 일관성 |
| 동작 | 탭 스와이프, 진입 애니메이션, 선택 pill, 눌림 반응, 숫자 전환 | 새로 도입하기보다 의미를 정리할 기반 |
| 접근성 | 최소 터치 크기, heading·stateDescription·progress semantics, 일부 차트 접근성 동작 | 전체 여정 검증으로 이어갈 기반 |

### 3.3 버튼과 전환의 현재 상태

- 상위 탭 스와이프는 현재 화면과 다음 화면을 함께 이동시키고 spring으로 완료·복귀한다.
- 일부 상위 화면은 320ms 진입과 50ms 간격의 단계적 노출을 사용한다. 최대 단계에서는 전체가 520ms에 걸쳐 나타난다.
- 하단 탭은 선택 표시 이동과 눌림·포커스 상태를 표현한다.
- 홈의 숫자와 진행률에도 상태 애니메이션이 있다.
- 일반 공통 버튼은 Material 3 wrapper이며, 업무 상태에 따른 누름 → 처리 중 → 저장 성공의 통합 사양을 보강할 여지가 있다.
- 조사 범위에서 명시적인 앱 햅틱 연동은 찾지 못했다. 시스템·라이브러리의 기본 진동까지 없다는 의미는 아니다.
- 하위 상세·세션·요약 사이에서 공유 요소 전환을 표현하는 공통 구조는 확인되지 않았다.
- Back callback 등록은 있으나, 제스처 진행률과 화면이 연동되는 predictive-back 연출을 구현했다고 볼 근거는 확인하지 못했다.
- 일부 컴포넌트에는 시스템 애니메이션 설정 확인이 있다. 앱 전체의 동작 축소 대응은 실기기 검증이 필요하다.

## 4. 유지할 제품 방향과 사용자 범위

기존 [UI 디자인 시스템](UI_DESIGN_SYSTEM.md)은 정밀함, 절제, 고급스러움, 운동 성과 중심을 지향한다. 고정 대표색은 `#38BDF8`이며, action·selection·focus·중요 metric에 제한해서 사용하도록 정의한다.

이번 제안은 이 방향을 유지한다. 기능·저장 계약·내비게이션 동작을 시각 개편에 묶어 임의로 변경하지 않는다.

초보자와 숙련자를 서로 다른 앱처럼 나누기보다, 같은 기본 흐름에서 필요한 깊이를 선택하게 한다.

| 사용 맥락 | 기본 화면 | 필요할 때 드러낼 정보 |
| --- | --- | --- |
| 처음 기록 | 무엇을 입력하고 완료하는지 명확한 안내 | 단위·RIR·부하 설명, 짧은 예시 |
| 반복 기록 | 지난 값 활용, 빠른 완료, 익숙한 위치 | 메모, 지난 운동 비교, 자주 쓰는 조정 |
| 세밀한 기록 | 핵심 수치에 즉시 접근 | 전체 세트 비교, 부하 설정, 상세 분석 |

설명과 고급 항목은 요청·펼침으로 제공하고, 사용자가 선택한 표시 방식을 유지하는 방안을 검토한다. 숙련도를 자동 추정해 기능을 숨기는 방식은 제안하지 않는다.

## 5. 개선 우선순위

### P1. 현재 세트와 지난 수행값을 가까이 연결

**확인된 구현:** 입력 카드 다음에 지난 기록과 적용 기능이 있어 비교와 입력이 세로로 떨어져 있다. 새 세트는 빈 입력으로 추가하며, 지난 기록을 적용하는 기능 자체는 이미 있다.

**제안:**

- 기존 한 줄 표 안에서 현재 입력 행 하나를 명확하게 강조한다.
- 현재 행 가까이에 해당 세트의 지난 수행값을 배치한다.
- `지난 값으로 채우기`, `방금 세트 값으로 채우기`를 명시적인 사용자 선택으로 제공한다.
- 완료 행의 숫자는 읽을 수 있게 남기고, 다음 입력 행의 우선순위를 높인다.
- 운동 이미지와 설명은 숫자 입력을 돕는 위치와 크기로 조정한다.

아래 값은 설계 설명용 예시이며 실제 기록이 아니다.

```text
벤치프레스                         2 / 4세트

지난번 이 세트     60 kg × 8회
                   [지난 값 채우기]

세트     중량       횟수      RIR      완료
  1      60 kg       8         2        ✓
  2      60 kg       8         2        □  ← 현재 행
  3       —         —         —
```

지난 값과 오늘 실제값을 구분한다. 값을 채우는 동작이 수행 완료를 자동 생성해서는 안 된다. 세트 추가는 기존 카드 안에 행을 붙이고, 초안·포커스·이미지 상태를 보존한다.

**기대 효과 가설:** 지난 기록을 찾고 기억하고 재입력하는 부담 감소.

### P1. 완료 체크·저장·휴식을 일관된 상태로 표현

**확인된 구현:** 완료 체크 성공 후 자동 휴식이 시작한다. 저장 상태의 접근성 설명은 있으나 저장 실패는 Toast로 전달한다. 수정으로 완료 체크가 풀리는 상태의 가시적 설명을 보강할 여지가 있다.

| 상태 | 제안하는 반응 |
| --- | --- |
| 누름 | 체크 영역이 즉시 반응하여 입력 접수를 알림 |
| 저장 중 | 해당 행 안에 처리 상태 표시, 초안 유지 |
| 저장 성공 | 체크 확정, 짧은 햅틱, 기존 휴식 표시 갱신 |
| 완료 후 수정 | `수정됨`으로 편집 중 값과 저장된 값 구분 |
| 저장 실패 | 행 가까이에 원인·재시도 표시, 입력값 유지 |
| 다음 세트 | 다음 행을 강조하되 키보드·스크롤을 강제로 이동시키지 않음 |

눌림 반응은 즉시 제공하고, 성공 표현은 실제 저장 성공 후 확정한다. 기존 체크와 메뉴 구조를 유지하며 저장·삭제 버튼을 행마다 새로 늘리지 않는다.

**기대 효과 가설:** 저장 여부에 대한 불확실성, 중복 탭, 실패 후 복구 부담 감소.

### P1. 운동 선택부터 완료 기록까지 시각적 연속성 확보

**제안:** 같은 운동의 이름·이미지·수행 상태가 선택, 상세, 휴식, 완료 요약에서 이어지도록 설계한다.

| 전환 | 제안하는 표현 |
| --- | --- |
| 운동 카드 → 상세  | 같은 운동명·이미지가 위치와 크기를 바꾸며 이어짐 |
| 세트 입력 → 휴식 | 실행 화면을 유지하며 휴식 영역의 숫자·상태 갱신 |
| 작은 휴식 표시 → 집중 보기 | 사용자가 누르면 같은 타이머가 확장 |
| 세션 완료 → 요약 | 실제 수행한 운동과 결과가 요약으로 정리되는 짧은 연출 |
| 뒤로가기 | 돌아갈 대상과 방향을 예측할 수 있는 전환 |

검수된 운동 이미지와 실제 기록의 연결을 앱의 기억점으로 삼는다. 이미지 소스·생성 카탈로그를 디자인 작업 때문에 다시 만들지 않는다. 근육 분류·선택 상태와 검증되지 않은 피로도·회복도 표현을 구분한다.

한 세트 완료의 표현은 짧게, 세션 완료는 상대적으로 풍부하게 구성한다. 반복 동작에 매번 긴 연출을 붙이지 않는다.

**기대 효과 가설:** 화면 이동 후 위치를 다시 찾는 부담 감소, 수행과 기록의 연결감 강화.

### P2. 식단 기록의 우선순위 정리

**확인된 구현:** 통합 검색, 카트, 영양 합계, 제거 Undo가 이미 있다. 일일 식단 화면에는 식품 관리, 외식 영양정보 관리, 연결·공개 진입점이 함께 노출되며 일부는 같은 동작을 호출한다. 검색 결과 영역에는 최대 288dp 높이 제한이 있다.

**제안:**

- 기본 화면을 날짜·섭취 현황·기록하기·오늘 기록에 집중시킨다.
- 관리·연결·공개 기능은 명확한 관리 진입점 아래 배치한다.
- `담기 → 담김 → 수량 수정 → 식사 저장`의 차이를 일관되게 표현한다.
- 검색 영역은 키보드와 가용 높이를 기준으로 검토한다.
- 검색어, 카트, 스크롤 보존과 미확인 영양값 표현을 유지한다.

**기대 효과 가설:** 첫 기록 경로의 발견성 향상, 한 끼 입력 도중의 주의 분산 감소.

### P2. 통계를 핵심 변화 → 비교 → 근거 순서로 구성

**확인된 구현:** 데이터 충분성, 볼륨, 빈도, 종목 성과, 체중, 기간 비교, 관찰 신호를 순차 배치한다. 일부 구현·저장 구조 설명도 기본 화면에 표시한다.

**제안:** 첫 화면은 최근 기간에 무엇이 달라졌는지 답하고, 사용자가 해당 요약을 누르면 차트와 원본 기록을 확인하도록 구성한다.

데이터가 충족될 때 사용할 수 있는 문장 예시는 다음과 같다.

- 최근 4주 운동 횟수가 이전 4주보다 늘었습니다.
- 이 종목은 같은 중량에서 반복 횟수가 증가했습니다.
- 체중 변화는 기록이 더 쌓인 뒤 비교할 수 있습니다.

비교 기간·단위·데이터 부족 여부는 기본 화면에 남긴다. 저장 구조 설명은 별도 정보 패널로 이동한다. 운동·식단·체중을 같은 기간으로 볼 수 있게 하되, 함께 변했다는 사실을 인과관계로 표현하지 않는다.

**기대 효과 가설:** 기록을 계속할 이유와 자신의 변화를 이해하기 쉬워짐.

## 6. 시각·인터랙션 원칙

### 6.1 화면 역할에 맞는 밀도

| 화면 | 중심 표현 |
| --- | --- |
| 메인 | 핵심 행동 하나와 오늘 상태를 먼저 읽는 여유 |
| 운동 중 | 숫자 정렬, 현재 행, 안정된 입력 위치 |
| 식단 | 검색 결과와 선택 항목의 빠른 비교 |

공통 토큰은 유지하되 모든 정보를 같은 크기와 강조의 카드로 만들지 않는다. 요약·입력·비교·완료의 배치 방식은 각 작업에 맞춘다.

### 6.2 브랜드색과 대비

기존 고정 브랜드 블루 `#38BDF8`을 유지한다. 다음 값은 불투명 sRGB 색상값으로 계산한 참고치이며 실제 화면의 접근성 통과·실패 판정은 아니다.

| 조합 | 대비비 |
| --- | --- |
| `#38BDF8` / `#FFFFFF` | 약 2.14:1 |
| `#1C1C1E` / `#38BDF8` | 약 7.94:1 |
| `#38BDF8` / `#090B0E` | 약 9.20:1 |

블루 면 위 핵심 글자는 충분한 대비를 확보하는 짙은 색을 검토한다. 색 이외의 체크, 문구, 형태로도 상태를 전달한다. 유리 효과 위에서는 실제 합성 결과로 대비를 다시 확인한다.

### 6.3 동작과 접근성

- 눌림 반응은 즉시 제공한다.
- 저장 성공·실패는 실제 업무 결과와 연결한다.
- 전환은 중단 가능하게 하고 애니메이션 종료가 다음 조작의 필수 대기가 되지 않게 한다.
- 잦은 세트 입력에는 짧고 정밀한 반응을 사용한다.
- 동작 축소 환경에서도 동일한 정보와 기능을 제공한다.
- Android 최소 48dp 터치 영역과 주변 간격을 함께 검증한다.
- 한 줄 세트 입력은 큰 글씨에서도 값을 접근할 수 있게 하고, 기존 가로 스크롤 정책을 보존한다.

## 10. 후속 작업 순서와 완료 기준

현재는 문서화 완료 후 대기 단계다. 아래 항목은 후속 작업 제안이며 이 문서 작성으로 구현을 시작하지 않는다.

| 순서 | 작업 단위 | 완료 기준 |
| --- | --- | --- |
| 1 | 운동 선택 → 세트 기록 → 휴식 → 완료 요약을 연결한 프로토타입 | 현재와 제안 흐름을 같은 과제로 비교할 수 있음 |
| 2 | 현재 세트·저장 피드백·휴식 연결 구현 | 입력 보존, 실패 복구, 연속 입력, 중단 후 복귀 검증 |
| 3 | 공통 버튼·입력·상태 규칙을 식단·신체에 확장 | 화면마다 조작법을 다시 배우는 부담 감소를 확인 |
| 4 | 메인·통계·완료의 시각 표현 강화 | 핵심 변화가 먼저 읽히고 근거 기록까지 접근 가능 |

초보·일반·숙련 사용자에게 같은 핵심 과제를 제시한다.

1. 한 세트를 입력하고 완료한다.
2. 지난 값을 활용해 다음 세트를 기록한다.
3. 여러 음식을 한 끼에 담아 저장한다.
4. 잘못 입력한 값을 수정한다.
5. 앱을 나갔다 돌아와 작업을 이어간다.

수행 시간, 입력·탭 수, 오입력, 중복 탭, 도움 요청을 비교한다. 큰 글씨, TalkBack, 좁은 화면, 라이트·다크, 동작 축소, 저장 실패, 화면 재생성도 별도로 검증한다. 개선 수치는 측정 전까지 목표 또는 가설로만 기록한다.

기능 구현 시 저장 경로와 입력 계약을 보존하고 최소 단위 테스트·빌드를 수행한다. 실기기, instrumentation, 운영 검증은 각각 분리해서 보고한다. 프로젝트 구조 변경이 수반되면 [정돈 리팩터링 규칙](FitnessApp_정돈_리팩터링_규칙.md)을 적용한다.
