# 재료 영양정보 파일

`내 식단 · 식품 관리`에서 JSON 파일을 고르면 등록 전에 새 재료, 값이 바뀐 재료, 이미 같은 재료 수를 확인합니다. 확인 후 변경 항목을 한 번의 로컬 DB 트랜잭션으로 적용합니다. 파일에서 빠진 항목은 자동 삭제하지 않습니다. 같은 내용을 다시 가져와도 중복 행이 생기지 않고, 등록 재료의 영양정보가 바뀌어도 이미 저장된 식단의 스냅샷은 유지됩니다.

시작 파일은 [ingredient-catalog.v1.example.json](ingredient-catalog.v1.example.json)입니다. 예제 영양값은 형식 설명용이므로 실제 기록 전에는 제공자가 확인한 값으로 교체하세요. 가져오기 형식은 `fitness.ingredient-catalog.v1`, UTF-8 JSON, 최대 1 MiB와 2,000개 재료입니다. `catalog_id`는 작성자 카탈로그의 고정 식별자, `revision`은 배포할 때 바꾸는 판 식별자입니다. 각 재료의 `id`는 카탈로그 안에서 고정으로 유지해야 합니다. 이름만으로 대조하지 않으므로 ID를 바꾸면 새 재료로 들어옵니다.

`basis_amount`는 아래 영양값의 기준량이고 `basis_unit`은 `g` 또는 `ml`입니다. `prep_state`는 `raw`, `cooked`, `as_served` 중 하나로 둡니다. `nutrients`에 열량(`calories_kcal`), 탄수화물(`carbs_grams`), 단백질(`protein_grams`), 지방(`fat_grams`)은 반드시 적습니다. 나트륨(`sodium_mg`), 당류(`sugars_grams`), 포화지방(`saturated_fat_grams`)은 선택입니다. 실제로 영양값이 0인 경우 `0`, 모르는 경우에는 선택 항목에서 키를 생략합니다.

제품의 포장 단위와 개당 용량은 이 재료 파일에서 입력하지 않습니다. 제품은 화면에서 브랜드, 영양표 기준량, 제품 1개 용량을 별도로 등록합니다. 직접 만든 요리는 파일에 조리 전후 재료를 조합해 임의로 만들지 않고 앱의 `내 요리` 편집기에서 재료량, 완성 인분 수, 선택한 조리 후 무게를 함께 저장합니다.
