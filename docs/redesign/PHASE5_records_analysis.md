- 기준 저장소: `Yeon-sik/Yeonsik-Fitness-App`
- 작성 시점 기준 main HEAD: `3795b01653857647832927b78f504a36b620cf8e`
- 실행 원칙: 각 Phase 시작 직전 반드시 최신 `main`을 다시 확인하고, 완료 후 코드 리뷰 결과에 따라 이후 Phase 명세를 수정할 수 있음
- 우선순위: 정확성 > 데이터 무결성 > 단순한 구조 > 유지보수성 > 개발 속도 > 미래 확장성
- 디자인 방향: 화이트/다크 테마 유지, 핵심 강조색은 Pastel Blue
- 언어 원칙: 운동명·식품명·브랜드명·제품명 등 고유명사는 원문 유지. 그 외 교체 가능한 UI 문구는 한국어로 통일. 하단 내비게이션 버튼의 라벨/구조는 별도 승인 없이 변경하지 않음.
- 금지: UI 작업을 이유로 DB schema, migration, 동기화 계약, PriceTrace/OCR 연계 계약을 임의 변경하지 않음


## 목표

저장된 사실을 빠르게 찾고, 앱의 해석과 명확히 분리해 보여준다.
기록 화면은 장식보다 scanability와 시간축 이해가 우선이다.

## 선행 조건

- PHASE 1~4 완료 및 리뷰
- 최신 main 재확인
- 기록/분석에 쓰는 source field와 계산식 확인

## 작업 범위

1. 월간 달력
   - 모든 날짜 셀의 강한 검정/흰 테두리 제거
   - 오늘: 얇은 outline
   - 선택일: Pastel Blue tonal container
   - 운동 / 체중 / 식단 marker는 색 + 형태를 함께 사용
   - marker는 최대 노출 개수를 제한하고 의미가 겹치지 않게

2. 선택 날짜 상세
   - 운동 / 체중 / 식사 기록을 동일 계층의 list/section으로 정리
   - 기록이 없는 경우 empty state는 간결하게
   - 수정 가능한 데이터와 readonly 기록을 명확히 구분

3. 운동 기록 상세
   - persisted record를 사실로 우선 표시
   - 수정 모드 진입 전에는 readonly
   - 세트 데이터는 숫자 정렬 및 row scanability 강화
   - template/current session UI와 의미를 혼동하지 않음

4. 체중 / 볼륨 변화
   - 차트는 데이터가 충분할 때만
   - 축/단위/기간이 명확하지 않은 decorative chart 금지
   - 현재 진행 중 값을 과거 완료 기록과 연결하지 않음
   - 기록 부족 시 숫자/리스트를 우선

5. 분석/발전 화면
   정보 계층을 명확히 분리:
   - 기록된 사실
   - 계산된 추세
   - 앱이 제안하는 검토 후보

   예:
   - 사실: 최근 체중 89kg
   - 추세: 최근 4주 +1.2kg
   - 검토 후보: 섭취량 또는 운동량 조정 검토

   의료 진단/처방처럼 읽히는 표현 금지

6. Pastel Blue 사용
   - 선택일
   - 핵심 분석 상태
   - 현재 보고 있는 기준
   에 한정
   기록 자체의 모든 요소를 파란색으로 칠하지 않음

7. 언어
   - 분석 화면의 번역 가능한 영어 eyebrow/상태/설명은 한국어화
   - 고유명사 유지
   - 동일 개념의 용어는 화면마다 번역이 달라지지 않도록 glossary 작성 권장

## 반드시 유지

- 기존 기록 자체의 값
- 날짜별 기록 연결
- read-only/edit 경계
- repository가 제공하는 저장값 우선 원칙
- 논문 기반 분석 엔진의 사실/권고 구분

## 비범위

- 분석 알고리즘 자체의 과학적 규칙 변경
- DB 집계 구조 변경
- 새로운 지표 추가

## 완료 조건

- 달력에서 날짜 숫자가 grid보다 먼저 보임
- 선택일/오늘/기록유형이 즉시 구분됨
- 사실값과 앱의 해석이 같은 스타일로 섞이지 않음
- 데이터가 부족할 때 차트가 억지로 그려지지 않음
- readonly와 edit 상태가 명확함
- 영어 장식 문구가 가능한 범위에서 한국어화됨

## 코드 리뷰 체크포인트

- chart가 UI convenience를 위해 데이터를 가공하면서 의미를 왜곡하지 않는가
- today/selected/current/in-progress를 동일 상태색으로 오용하지 않는가
- 분석 문구가 의료적 확정 표현으로 강화되지 않았는가
- 기록 수정이 과거 사실과 template을 혼동하지 않는가
