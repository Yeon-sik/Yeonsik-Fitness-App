## 일반 세트의 기존 Android 동작

같은 A25 격리 설치본에서 파운드를 선택하고 `ParityBench` 루틴에 바벨 플랫 벤치 프레스 한 종목을 담았다. 아래 값은 앱 화면을 조작한 뒤 테스트 앱만 강제 종료하고 해당 Room 파일을 다시 읽은 결과다.

| 시점 | 첫 세트의 원래 입력 | DB 중량과 상태 |
| --- | --- | --- |
| 완료 체크 후 첫 재실행 | 95 lb × 8회, RIR 3 | 43.09127515 kg, 운동 진행 중 |

| 두 번째 재실행 → 운동 완료 → 기록 상세 재조회 | 100 lb × 10회, RIR 2 | 45.359237 kg, 완료 세트 1개, 총 453.59237 kg |

세 시점의 운동·종목·첫 세트 ID가 모두 같았다. 운동 완료 직후에는 운동 요약이 열렸다. 앱을 다시 열어 기록 탭의 `상세 보기`를 누르면 같은 세트의 원래 입력 단위와 횟수가 보였다. 이 경로를 공통 세트 편집기의 전후 비교에 사용한다.

## 일반 세트 편집기 전환 비교

일반 세트의 입력 열, 완료 체크, 삭제 버튼, 단위 선택과 입력 취소를 공통 Compose에서 그린다. 공통 입력 규칙은 빈칸과 숫자 0을 구별하고, 횟수만 바꾸면 기존 중량과 원래 입력 단위를 보존한다. Android는 기존 Room 62를 사용한다. iOS 운동 파일 v3는 미완료 행을 저장하고 v1·v2의 기존 세트를 완료 상태로 읽는다.

Android 16 에뮬레이터의 1080 × 2424 화면에서 시스템 바를 제외한 같은 영역(가로 1080, 세로 2264픽셀)을 비교했다. 일반 세트 재진입, 큰 글꼴 다크 모드, 종목 이력 세 화면의 전후 차이는 각각 0픽셀이었다. 밝은 화면을 체크 직후 촬영한 첫 비교에서는 버튼 주변 픽셀이 달랐다. 재진입 비교에서는 A25 격리 설치본에서 가져온 변경 전 APK와 변경 후 APK에 동일한 계측 APK를 사용해 아무 입력 칸도 누르지 않은 상태를 캡처했다. [세 화면 전후 비교](evidence/android-sets-stage2.webp)

A25의 격리 앱을 공통 편집기로 덮어 설치하고 같은 루틴으로 새 운동을 기록했다. 위 표의 세 시점마다 기존 완료 운동과 새 운동을 함께 조회했다. 기존 기록은 그대로였고 새 운동의 원래 입력과 환산 중량·반복·RIR·상태·누적 볼륨은 변경 전과 모두 같았다. 두 번의 강제 종료와 재개 중 새 운동·종목·첫 세트 ID가 유지됐다. 완료 직후 요약에서 1세트·1,000 lb를 확인했다. 재실행 후 기록 탭의 선택일 목록에서 최근 운동 상세를 열어 100 lb·10회와 이전 운동 대비 볼륨 차이 0을 확인했다.
