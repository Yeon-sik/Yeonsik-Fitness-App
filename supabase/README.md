# Supabase layout

FitnessApp has one active remote database target:

- `shared/supabase/`: migrations for the same Personal OS Supabase project used
  by CashOS and PersonalOSApp.
- `.env`: ignored local build configuration generated by
  `../scripts/configure-shared-supabase.ps1`.

The nutrition catalog is a table group inside the shared project. It is not a
separate Supabase project and does not have a separate login or token store.
Apply the migrations in `shared/supabase/migrations/` only after confirming the
linked project ref matches the project shown by the configuration script.

```powershell
supabase link --project-ref <shared-project-ref> --workdir supabase/shared
supabase migration list --linked --workdir supabase/shared
supabase db push --linked --dry-run --workdir supabase/shared
supabase db push --linked --yes --workdir supabase/shared
supabase db lint --linked --workdir supabase/shared
```

Files labeled `Remote history marker` represent versions already applied by
another child repository. They intentionally contain no schema SQL: they keep
the Supabase CLI history check intact without copying or re-running another
app's migration. The authoritative SQL remains in that owning repository. This
directory is an incremental deployment target, not a blank-database bootstrap.

The formerly separate Nutrition Supabase project is legacy-only. Its remote
project is not deleted by this repository change, and its rows are not migrated
automatically. Export/import any real legacy rows deliberately before retiring
that remote project.
